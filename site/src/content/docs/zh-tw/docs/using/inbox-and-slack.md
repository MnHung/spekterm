收件匣收集從外面來的工作，目前主要是 **Slack 上提及你的訊息**。每一則都會等你讀過。你接受之後，spekterm 會在你確認的資料夾開一個 `claude` session，把訊息當作脈絡交給 agent，並填好第一則 prompt，但**不會送出**，要由你按 `Enter`。

按活動列（最左邊那一欄）上的 **交接** 打開收件匣。這個入口會顯示有幾則在等你處理。

## 審閱一則項目

在打開任何東西之前，每一則都會列出來源、作者、時間，以及**全文**。內容以純文字呈現，和 agent 將收到的完全相同。

- **開在** 顯示這一則會開在哪個資料夾。spekterm 依你的 routing 規則預選一個，你也可以改選別的。資料夾確認之前，什麼都不會開。
- **接受** 會在那個資料夾開一個 `claude` session。這一則的內容會當作脈絡交給 agent，agent 的輸入處也會填好一則指向它的 prompt。讀過、想改就改，再按 `Enter` 送出。
- **忽略** 會移除這一則，不開任何東西。

接受過的項目會顯示 **已開啟**，直到你按 **從收件匣清除** 為止，方便你回頭重讀接受過的內容。

別人寫的內容絕不會自動送給 agent。你要先審閱，第一則 prompt 也會等你按 `Enter`。在已配對的手機上接受的項目，prompt 則會等你在手機上讀過、從手機送出（[遠端存取](/zh-tw/docs/using/remote-access/#從手機送出收件匣項目的-prompt)）。

## 排程分頁

收件匣把現在要處理的與計畫中的分開放。**收件匣** 分頁列出現在要處理的項目；**排程** 分頁列出所有計畫中的事，分成三段：

- **待核准**：agent 提議的重複交接（[交接](/zh-tw/docs/using/handoffs/#交接會重複的工作)）。每一份都附上排程、接下來會開啟的時間、結束時間與全文。你可以把它**核准**到你選的資料夾，或**拒絕**它。結束時間已過的提議不能再核准。分頁標籤上會顯示有幾份提議在等。
- **已排程**：所有在等時間到的交接，最早的排在最前面，包括排到之後某個時間的交接（[交接](/zh-tw/docs/using/handoffs/#把工作交接到未來的某個時間)），以及每個重複交接的下一次。每一筆都附上開啟時間、來源、要開在哪個資料夾，以及全文。**立即執行** 會馬上開啟，就像時間已經到了；**取消** 會丟掉一次性的交接，**跳過這次** 則只丟掉重複交接的這一次。
- **週期**：每個已核准的重複交接，附上下一次的時間，或沒有下一次的原因（較早的一次還在收件匣等你處理，或收件匣已滿）。**停止重複** 會結束它，動手前會先問你。

提議是在等你處理，所以會計入收件匣入口的數字，也會發通知；已排程的交接在開啟之前兩者都不會。如果通知只跟提議有關，從通知打開收件匣時會直接顯示排程分頁。不論是不是計畫中的，每一則都計入收件匣等待項目的上限。

## 通知

有新項目到達時，spekterm 會發出桌面通知。同時到達的好幾則會合併成一則通知。點通知會把 spekterm 帶到前景，並打開收件匣。

## Routing 規則

**Routing 規則** 分頁決定一則項目預選哪個資料夾。

- 規則由上往下比對，第一條符合的勝出。每條規則指定一個欄位（**比對欄位**）、這個欄位必須包含的文字（**包含**），以及要開在哪個資料夾（**開在**）。用箭頭按鈕調整規則的順序。
- 沒有規則符合時，會用 **預設資料夾**。請設定一個；沒設的話，每一則抵達時都沒有選好資料夾，你每次都得自己挑。
- 有些欄位（例如標題與訊息內容）是投遞者自己寫的。以這些欄位為條件的規則會有標示，因為投遞者可以刻意措辭，左右項目開在哪裡。

規則指向的資料夾如果已經不在工作區裡，這一則會直接說明，不會悄悄開到別的地方。

## 連接 Slack

Slack 連線在 **設定 → 整合** 設定，用來連接你的 Slack 帳號。連上之後，spekterm 會找出提及**你**（token 所屬的那個人）的訊息，把每一則變成收件匣項目，並附上討論串到那則訊息為止的內容作為脈絡。討論串太長時會截短，項目裡也會註明。

你需要在 Slack workspace 裡有一個 Slack app，以及它的 **user token**。替 token 加上這些 user token scope：

```text
channels:history  groups:history  im:history  mpim:history
channels:read     groups:read     im:read     mpim:read
users:read
```

`*:history` 讓 spekterm 讀得到訊息，`*:read` 讓它列得出你所在的對話，`users:read` 則把使用者 ID 換成人名。改過 scope 之後，要重新安裝 app，再重新複製 token。把 token 貼到 **User token** 底下，按 **儲存** 或 **Enter**。離開欄位不會儲存，所以貼到一半的 token 不會被存下來。spekterm 會從 token 讀出你的身分，沒有其他東西要填。

還沒設定 **預設資料夾** 時，「整合」分類會提醒你：提及抵達時沒有資料夾可開。按那裡的 **開啟路由規則** 按鈕，就會打開收件匣的 routing 規則。

### 提及什麼時候抵達

spekterm 會在啟動時、每五分鐘，以及你剛存下 token 時檢查新的提及。**回補範圍** 限制每次檢查最遠往回找多久。spekterm 關著時發生的事，Slack 不會重送，所以啟動時已經早於這個範圍的提及會漏掉。新的範圍在按 **Enter** 或離開欄位時套用。

在 macOS 上，關掉視窗不會結束 spekterm。它在沒有視窗的狀態下繼續執行時，收件匣照常收件，每五分鐘一次的檢查也會繼續。

想在幾秒內收到提及，就再加一個 **app-level token**：替你的 Slack app 開啟 Socket Mode，再替它建立一個 app-level token。之後 **即時更新** 會顯示即時連線有沒有開著。連線中斷時，spekterm 會改回定期檢查。

### 狀態

「整合」分類隨時會顯示連線的狀態：尚未設定、運作中但沒有新項目、上一次檢查帶進了幾則提及、Slack 要求放慢，或是憑證失效、缺少 scope。連線壞掉絕不會看起來像「沒有人提及你」。連線壞掉期間，收件匣也會顯示一行 Slack 狀態，附一個打開「整合」分類的按鈕。

### 你的 token

token 存在 spekterm 的資料目錄（Linux 上是 `~/.config/Spekterm`，macOS 上是 `~/Library/Application Support/Spekterm`），只有你的使用者能存取。token 只會送到 Slack，或送到 **API 端點** 設定的端點。除非你清楚原因，否則不要改這個端點：不是 `https` 的位址會被拒絕，端點維持原樣。token 絕不會進到你的終端機或 agent。詳見[資料與網路](/zh-tw/docs/reference/data-and-network/)。

## 被拒絕的投遞

收不進收件匣的項目不會被悄悄丟掉。項目讀不出來、內容太長而無法審閱，或指名了不在工作區裡的 repository，都會被拒絕。收件匣會逐一列出每則拒絕與原因，直到你清除為止，重啟之後也還在。
