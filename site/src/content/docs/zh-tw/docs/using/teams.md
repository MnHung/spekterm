**團隊**是一群共用一台小 server 的 spekterm 使用者，這台 server 由團隊自己架設：[spekterm-server](https://github.com/spekhq/spekterm-server)。加入團隊之後，agent 才能把工作交給隊友，而不只是交給你自己的 repo。這一頁說明加入與連線；把工作交給隊友的方式寫在[交接](/zh-tw/docs/using/handoffs/)。

這個功能預設**關閉**；在你加入團隊之前，spekterm 不會為它連到任何地方。

## 加入

團隊的管理者在 server 上建立邀請，傳給你一個以 `spekterm://join` 開頭的連結。

1. 打開 **設定 → 團隊**，開啟 **加入團隊**。
2. 把連結貼進 **邀請連結**，按 **繼續**。spekterm 會向 server 詢問這份邀請的用途（不會用掉它），並顯示團隊名稱，以及這份邀請是讓你成為**新成員**，還是把**這台電腦**加到你既有的成員資格下。
3. 新成員要選一個 **handle**（1–32 個 `a`–`z`、`0`–`9` 與 `-`，之後不能更改）和 **顯示名稱**。每一種邀請都要為 **這台裝置** 取名（預設填入電腦名稱）。
4. 按 **加入**。

邀請只能用一次，而且會過期（預設七天，除非管理者另外設定）。如果 handle 已被使用，換一個即可，邀請仍然有效。

如果邀請帶有憑證指紋（server 使用自己簽的憑證），spekterm 只信任那一張憑證；否則照一般方式驗證 server 的憑證。

## 收到隊友的交接

隊友交給你的交接會出現在你的[收件匣](/zh-tw/docs/using/inbox-and-slack/)，標著**隊友**，附上他的顯示名稱與團隊名稱 —— 這些取自 server（它知道是誰送的），從不取自內文。spekterm 關著時，會在下次啟動時出現。你有多台裝置時，它只會到其中一台。

它和其他別人寫的收件匣項目一樣處理：你先讀完整本文、選資料夾、再接受；新 session 的第一則 prompt 會填好但**不送出**，等你自己送。它的本文最長可到 20,000 字元 —— 與你自己 repository 之間的交接同一個上限，比其他收件匣項目長。

如果這台裝置在交接抵達途中被移出團隊，spekterm 仍然會顯示它，並附上一行說明它可能也送到了你的另一台裝置。

隊友會在他的**已寄出**清單裡看到這則交接的後續（見[交接](/zh-tw/docs/using/handoffs/)）：

- 你為它開的 session 開始工作時（也就是你送出第一則 prompt 之後），他會看到**已接手**。只按下接受、或 prompt 填好了還沒送出，都不會告訴他任何事。
- 收件匣項目上的**婉拒…**讓你拒絕，可附上最多 500 字元、他會讀到的理由。**忽略**什麼都不會告訴他：他會一直看到「已送達」。
- 那個 session 裡的 agent 會被告知它的完成報告會送給隊友。它寫的每一份報告都會以**已完成**送給隊友，你也會收到平常的通知。如果團隊 server 不再收這則交接的報告（例如已經收了十份），或你離開了團隊，spekterm 會在收件匣與通知裡說明，agent 下一份報告也會附上原因被拒絕。
- 不支援這項功能的舊版團隊 server 不會出現**婉拒…**，也不會告訴 agent 它可以回報。

## server 看得到什麼

server 由你的團隊架設，**它的管理者讀得到經過它的所有內容**，包括交接：沒有任何端對端加密。它會保存你的 handle、顯示名稱、你各台裝置的名稱、團隊的成員清單，以及每則交接的標題與本文，直到送達或過期為止（之後只留下誰送給誰、何時）。回傳的婉拒理由或完成報告會保存到寫下之後 30 天；每則交接的紀錄（誰、送給誰、何時、狀態）會保存到最後一次變動之後 90 天，讓你在另一台裝置上也能重建已寄出清單。見[資料與網路](/zh-tw/docs/reference/data-and-network/)。

**經 server 連進來的手機。** 如果 server 提供這項功能，你可以讓已配對的手機在離開這台電腦的網路時，經 server 連到這台電腦。server 只轉送加密過的連線、讀不到內容；它看得到是哪支手機、什麼時候、連了多久、傳了多少。預設關閉，在**設定 → 團隊**打開。見[遠端存取](/zh-tw/docs/using/remote-access/#經團隊的伺服器)。

你這台裝置的憑證只在加入時給一次，存放在你電腦上 spekterm 的機密檔裡，和 Slack 憑證放在一起。spekterm 絕不會把它放進終端、agent 的環境變數，或任何寫給 agent 的檔案。這個檔案沒有加密：以你的使用者帳號執行的程式（包括有 shell 的 agent）讀得到它。

## 連線

功能開著時，spekterm 對 server 維持一條連線，斷線就重連，每次間隔逐漸拉長（最長五分鐘）。**設定 → 團隊** 會顯示狀態：已連線、重新連線中（以及下一次嘗試的時間），或已停止。關掉功能會關閉連線，但保留你的成員資格。

遇到只有你能處理的狀況時，它會**停下來**並說明原因，在設定清單上標示 **團隊**，並發一則桌面通知：

| 停下來的原因 | 怎麼辦 |
|---|---|
| 這台裝置已被移出團隊 | 管理者撤銷了這台裝置，或把你移出團隊。要再加入需要新的邀請。 |
| 另一個 spekterm 正在使用這台裝置的憑證 | 同一份設定的兩個副本（例如從備份還原的）會互相取代。在你要用的那一個按 **重新連線**。 |
| spekterm 和 server 使用的協定版本不同 | 訊息會說明哪一邊比較舊：更新 spekterm，或請管理者升級 server。 |
| server 的憑證變了 | 請管理者發一份新的裝置邀請，然後貼上。 |
| 在這台電腦上找不到憑證 | **重新連線** 會再讀一次。如果真的不見了，按 **從這台電腦移除**，並請管理者撤銷這台裝置、發一份裝置邀請。 |

## 為這台裝置改名，以及離開

連線時修改 **這台裝置**，按 Enter；保存的是 server 回應的名稱。

**離開團隊** 會先確認你有幾台裝置，再告訴你會發生什麼事：從最後一台裝置離開，會**把你移出團隊**並釋出你的 handle；從多台中的一台離開，只有這台裝置離開。離開需要連線。沒有連線時，**從這台電腦移除** 會讓這台電腦忘掉團隊，而在管理者撤銷之前，server 仍會列出這台裝置。
