spekterm 裡的 Claude Code session 可以把工作交接給工作區裡的另一個 repository。假設 `api-server` 裡的 agent 改了一個 endpoint，`web-app` 的 client 也得跟著改。agent 寫一份交接，spekterm 就會在 `web-app` 開一個新的 `claude` session，把交接內容交給它，並送出第一則 prompt。新的 session 記得自己從哪裡來，做完時會回報。

## agent 怎麼知道自己可以交接

`claude` session 啟動時，spekterm 會告訴 agent 三件事：它正在 spekterm 裡執行、工作區裡有哪些 repository 可以交接，以及怎麼投遞交接。你不需要做任何設定，用平常的話說就好：

> 把 client 端的修改交接給 web-app。

agent 會寫一個簡短的標題，以及一段描述工作的內容。spekterm 讀到交接後，依名稱在工作區裡找到目標 repository，並在那裡啟動 session。

和來自 Slack 的收件匣項目不同，交接**不會先問你**就直接開好，因為內容是你自己 session 裡的 agent 寫的，不是第三方。新的 agent 一就緒，第一則 prompt 就會送出。偶爾 CLI 沒有接到送出鍵，這時 session 會顯示 **有一則 prompt 正等著被送出**，請自己按 `Enter`；spekterm 不會再送第二次。

## 把工作交接到未來的某個時間

一個 change 常常要好幾天才能收尾：最後幾步要等部署、等資料累積，或等 review。這時可以請 agent 把剩下的工作交接到之後的時間：

> 把驗證的部分交接給這個 repo，明天早上 9 點開始。

agent 會在交接上加上時間。spekterm 會趁 agent 還在的時候立刻檢查這份交接：目標不存在、內容太長，或時間無法使用，都會當場拒絕。通過檢查的交接會放在收件匣的 **已排程**，時間到了才開 session。開的一律是新的 session，方式和立即開啟的交接一樣。

- **只在 spekterm 開著時執行。** 時間到時 spekterm 如果關著，下次啟動時就會直接開，不再問你。新的 agent 會知道原定的開始時間與實際開始的時間，自己判斷中間變了什麼。
- **已排程的交接會安靜等待。** 開啟之前不發通知，收件匣入口也不計數。開啟時才像一般到達的交接一樣通知你。
- **立即執行** 會馬上開啟，**取消** 會把它丟掉。已配對的手機兩者都能做。
- 時間必須帶時區，最多只能排到 30 天後。已經過去的時間會立刻開啟。

每份交接**最多自動開啟一次**。那次開啟如果沒有成為一個能用的 session（資料夾被移除了，或 session 起不來），這份交接會以一般項目留在收件匣，等你接受；spekterm 不會再試。

## 交接會重複的工作

有些工作會定期回來，例如每週三晚上的回顧、每個工作日早上的檢查。直接請 agent 安排：

> 每週三晚上 9 點，在這個 repo 開一個 session 整理這週的回顧。到年底為止。

agent 會寫一份帶有 **重複排程** 的交接。排程用 cron 格式，以你電腦的時區解讀，例如 `0 21 * * 3` 是每週三 21:00。agent 也可以設定排程從何時開始、到何時結束；沒有結束時間的話，會一直重複到你停止為止。

**重複的交接是一份提議，不是排程。** 你核准之前什麼都不會開。它像一般交接一樣進收件匣（會通知、會計數），放在 **排程** 分頁，附上排程、接下來會開啟的時間、結束時間與全文。你可以把它**核准**到你選的資料夾，或**拒絕**它。核准不會馬上開任何東西，第一個 session 要到排程上的第一個時間才開。

- **每一次都開一個新的 session。** 它的 agent 會知道這份交接會重複，也會知道這一次原定何時開始、實際何時開始。
- **只在 spekterm 開著時執行。** spekterm 關著（或電腦睡著）時錯過的那幾次，下次啟動時**只跑一次**，不會每次各跑一次。agent 會知道它代替的是哪幾次。
- **一次只排一次。** 收件匣只列出下一次。**立即執行** 會馬上開啟，這一次就算完成，接著排再下一次。**跳過這次** 只丟掉這一次。
- **某一次開不起來時，排程會暫停。** 資料夾被移除了，或 agent 事件回報被關掉時，就會發生這種情況。失敗的那一次會留在收件匣讓你看到，在你接受或忽略它之前，不會再排下一次。否則資料夾已經不在的排程，每週都會多出一筆失敗。
- **停止重複** 會結束排程。它在 **排程** 分頁的週期清單裡，按下後會先請你確認。排程已經開過的 session 不受影響。
- 排程最多每小時開一次（分鐘只能是單一數字），而且未來四年內必須至少有一個時間。
- 已配對的手機可以拒絕提議，也可以立即執行或跳過某一次。核准與停止只能在電腦上做。

## 追蹤交接出去的 session

- 新 session 的分頁以交接的標題命名。**開啟交接單** 隨時都能看交接內容與最新的結果。
- 在同一個 repository 裡，交接出去的 session 會在 rail 上縮排在來源 session 底下。跨 repository 時，子 session 會標示 **來自** 它的母 session，母 session 則標示它交接出去了幾個 session。點任一邊就能跳到另一邊。
- 每個交接出去的 session 都有一個狀態，母子兩端都看得到：**進行中**、**等你** 或 **已完成**。**等你** 跟著 session 的圓點走：你看過那個 session 之後就不再顯示狀態，直到它再次開始工作（見[圓點代表什麼](/zh-tw/docs/using/terminals-and-sessions/#圓點代表什麼)）。

子 agent 做完時會寫一份簡短的報告。spekterm 會把 session 標成 **已完成**，在交接單裡顯示摘要，並發出桌面通知；點通知會打開交接單。子 agent 也可以直接把結果傳給母 agent（見下方）。

**已完成** 的 session 收到新的工作就會重新開始。spekterm 絕不會自己關掉它，不過你請 agent 關的話，agent 可以關（見下方）。已完成的 session 可以逐一關閉，也可以一次全部收掉：從母 session 的子 session 清單收，或用全工作區的動作收，這個動作在至少有一個 session 已完成時才會出現。兩種方式都會先問你，並列出每個 session 的結果。

## agent 之間互相傳訊

spekterm 裡的每個 `claude` session 都以固定的名字執行，名字由它的 rail 項目加上一段短碼組成，例如 `web-app-3f9a`。這個名字跨重啟、跨喚醒都不變。agent 透過這些名字使用 Claude Code 自己的本機 session 訊息功能：子 session 可以告訴母 session 它做完了，同一個母 session 交接出去的兄弟 session 也能互相協調。spekterm 會隨時更新每個 agent 的親屬清單：它的母 session、兄弟 session，以及子 session 和子 session 再交接出去的 session（一路往下）。訊息本身由 Claude Code 傳遞。

休眠中的 session 沒有行程，在你喚醒它之前收不到訊息。agent 會被告知這一點，也會被告知不能自己去喚醒 session。

給每個 session 固定的名字有一個副作用：Claude Code 會把這個名字顯示成終端機標題。想在分頁上看到任務名稱，就替分頁重新命名，你取的名字會優先。

## 請 agent 關閉、休眠或改名 session

agent 可以關閉、休眠或改名自己的 session，以及它交接出去的任何 session，包括那些 session 再交接出去的。直接用白話說：

> 這裡做完了，把這個 session 關掉吧。
>
> 把你交接出去、已經做完的都休眠。

- **關閉** 會結束 session，並把它從工作區移除，跟關掉分頁一樣。**休眠** 會結束它的行程，讓它保持休眠，直到你喚醒它。**重新命名** 會改分頁上的名稱。
- **關閉和休眠會等那個 session 這一輪結束才執行。** 還在工作的交接 session 會在停下來時才關，不會在中途被切斷。重新命名則立刻生效。
- **agent 不會自己把自己的 session 關掉。** 它要求關閉時，會先把回覆講完。接著 session 上會出現 **agent 要求關閉這個 session**，附 **關閉** 與 **保留**。底下的回覆照樣看得到、捲得動，你按 **關閉** 之前什麼都不會關。在那個 session 裡打字，就等於選了保留。已配對的手機上也會出現同一個提議，也能回應（[遠端存取](/zh-tw/docs/using/remote-access/)），在任一邊回應，兩邊都算數。
- **在那個 session 裡打字，會取消等待中的關閉或休眠**，因為你已經把它拿回來了。你自己休眠、關閉或喚醒它，效果也一樣。spekterm 結束時，等待中的指令也會被丟棄。
- agent 只能動自己這一支底下的 session。要它關掉母 session、兄弟 session 或不相關的 session，指令會被拒絕，你會看到一則通知，收件匣裡也會留下紀錄。
- 畫面不會跳動：rail 上的選取和你的鍵盤焦點都留在原處。

agent 收到的指令回條（見下方）只說指令被接受或被拒絕，不說有沒有執行完。至於它交接出去的 session，agent 可以從親屬清單看到結果：不見了、沒在執行，或改了名。

## 交接失敗時

送不到的交接不會無聲無息地消失。agent 指名了不在工作區裡的 repository（或兩個資料夾共用的名稱），或寫了太長而無法審閱的內容時，spekterm 會發出通知，並在收件匣留下一則附上原因的紀錄，直到你清除為止，重啟之後也還在。

## 回條：agent 會知道什麼

agent 寫給 spekterm 的每一個檔案（交接、完成報告或指令），spekterm 都會寫一張 agent 讀得到的**回條**，內容是下列其中一種：

- **已接受**；
- **已排程**，附上時間；
- **待核准**：重複的交接正在等你核准；
- **重複**；
- **已拒絕**，附上原因，以及再試一次有沒有用；
- **暫緩**：還沒處理，spekterm 之後會再讀一次。

agent 事後不會知道你有沒有核准它的提議。

有了回條，agent 可以說「交接已被接受」，而不只是「我寫了」；即將被關掉的 agent 也能趁還來得及修正時，知道自己被拒絕了。

回條記的是 spekterm 讀到那個檔案時做了什麼，不代表新的 session 已經把工作做完；那要看子 session 自己的報告。另外，已接受的交接在開啟時還會再檢查一次。如果那時資料夾已被移除，看到失敗的是你，不是 agent。

## 交接不是什麼

- **不是安全邊界。** 有 shell 的 agent 想交接就能交接，就像它能執行任何指令一樣。交接只會在已經在你工作區裡的資料夾開 session。
- **沒有次數上限。** agent 想交接幾次都可以。
- **不是給別人的。** 交接是在你自己的機器、你自己的工作區裡開 session。
