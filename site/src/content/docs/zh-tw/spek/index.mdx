## spec 是寫來讀的

OpenSpec 把專案的 requirement 以及每一次對它的修改，都存成 `openspec/` 底下的 Markdown 檔。這個格式適合 agent 撰寫、適合 git 追蹤，卻不好讀：一個 change 就是 proposal、design、task 清單，再加上每個 capability
一份 delta，散在十幾個檔案裡。spek 讀這個目錄並把它排好 —— 有結構、spec 與 change 互相連結，進度一眼就看得到。

## spek 與 spekterm

spek 的引擎也替 [spekterm](/zh-tw/) 讀 OpenSpec：spekterm 的側欄用 spek 的核心套件（`@spekjs/core`）掃描 spec 與 change，也畫 spek 的關係圖與時間軸（`@spekjs/ui`）。spek 讓你在平常工作的地方讀 spec；spekterm 是在 spec 旁邊跑 Claude Code session 的桌面工作台。兩者誰也不需要誰。
