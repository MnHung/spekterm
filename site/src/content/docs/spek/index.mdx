## Specs are meant to be read

OpenSpec keeps a project's requirements and every change to them as Markdown files under `openspec/`.
That is the right format for an agent to write and for git to track, and a hard one to read: a change is a
proposal, a design, a task list, and a delta per capability, spread over a dozen files. spek reads that
directory and lays it out — with structure, links between specs and changes, and progress you can see at a
glance.

## spek and spekterm

spek's engine reads OpenSpec for [spekterm](/) too: spekterm's side panel uses spek's core package
(`@spekjs/core`) to scan specs and changes, and draws spek's graph and timeline (`@spekjs/ui`). spek is for
reading specs where you already work; spekterm is a desktop workbench for running Claude Code sessions next
to them. Neither needs the other.

## Open source

spek is MIT-licensed, and its source is on [GitHub](https://github.com/spekhq/spek). It has no account,
no telemetry, and no analytics; [Data and network](/spek/docs/reference/data-and-network/) lists what each
form connects to.
