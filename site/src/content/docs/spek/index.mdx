## Specs are meant to be read

OpenSpec keeps a project's requirements, and every change to them, as Markdown files under `openspec/`.
The format is easy for an agent to write and for git to track, but hard to read: one change is a proposal,
a design, a task list, and a delta per capability, spread over a dozen files. spek reads the directory and
lays it out with structure, links between specs and changes, and progress you can see at a glance.

## spek and spekterm

spek's engine also reads OpenSpec for [spekterm](/). spekterm's side panel scans specs and changes with
spek's core package (`@spekjs/core`) and draws spek's graph and timeline (`@spekjs/ui`). spek is for reading
specs where you already work; spekterm is a desktop workbench that runs Claude Code sessions beside them.
Neither needs the other.

## Open source

spek is MIT-licensed, and its source is on [GitHub](https://github.com/spekhq/spek). spek itself has no
account, no telemetry, and no analytics. [Data and network](/spek/docs/reference/data-and-network/) lists
what each form connects to.
