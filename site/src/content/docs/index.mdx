## Not four terminal tabs and an editor

Running agents across several repositories usually means a stack of terminal tabs, plus an editor you
switch to just to read the spec. spekterm puts every repository's sessions in one window and keeps the
spec in view. Its side panel understands OpenSpec: it shows the change the agent is working on and
updates as the agent writes to disk.

## Sessions that last

<Screenshot
  wide
  src={terminal}
  alt="A shell session showing git log and the change's files, next to the side panel showing the change's proposal."
  caption="Real terminals, several per repository, beside the change's proposal."
/>

- **Real terminals** — `claude` and your login shell in real ptys, several per repository, git
  worktrees included.
- **They survive a restart** — `claude` sessions resume their conversation; shells come back with the
  previous screen replayed, in their last directory (on macOS, in their folder).
- **Hibernate what you are not using** — by hand, or automatically after a day idle. A hibernated session
  ends its process and stays dormant until you wake it.

## Read the agent, not just its terminal

Switch an agent session to the conversation view to read the exchange as messages and tool calls. The
view is built from the agent's own transcript and hooks; spekterm never scrapes the screen. The terminal
is always one click away.

- **Inbox** — when someone mentions you in Slack, the mention lands in the inbox. Accept it to get a
  Claude Code session in the repository you choose, with the context already filled in.
- **Handoffs** — an agent can hand work to another repository's agent. spekterm opens the new session,
  and you can follow both ends of the handoff until the work is reported done.

## How it works

<Steps>

1. **Add your repositories** to the workspace.
2. **Start a Claude Code session** in one of them — or a shell, or both.
3. **Follow the change** in the side panel while the agent works, and step in whenever you want.

</Steps>

## Local-first, open source

spekterm is a desktop app: your repositories, sessions, and settings stay on your machine. It has no
account, no telemetry, and no update check. The programs it starts for you, the `claude` and `openspec`
CLIs, make their own connections. [Data and network](/docs/reference/data-and-network/) lists exactly
what connects where. spekterm is MIT-licensed, and its source is on
[GitHub](https://github.com/spekhq/spekterm).

## Built on spek

<SpekLogo />

[spek](/spek/) is spekterm's sibling project, from the same maintainers: an open-source, read-only viewer
for OpenSpec content. It runs in your browser, in VS Code, in a JetBrains IDE, or as a static page your CI
builds. spekterm's side panel is built on spek's work:

- **The engine that reads OpenSpec** — scanning specs and changes, task progress, and worktree
  aggregation come from spek's core package, `@spekjs/core`.
- **The Graph and the Timeline** — the same components spek draws, from its `@spekjs/ui` package.
- **The mark** — spekterm's icon is spek's S with a terminal prompt beside it.

The side panel itself is spekterm's own, made for a narrow column next to a terminal. Use spek to read
specs where you already work; use spekterm when you drive agents across repositories and want the spec
beside them. They read the same files, and neither needs the other.
